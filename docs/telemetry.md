# Connected telemetry contract

Flowra keeps internal browser simulation separate from Connected device mode. Connected data is never generated by the dashboard. Only authenticated, validated HTTP frames populate that mode. This version accepts one configured device with a **Connected simulated ESP32** or **Connected HTTP test sender (simulated)** source label; it does not certify physical sensor input. Source labels are sender-declared, not device attestation.

## Configure locally

`.env.local` contains the separate `FLOWRA_INGEST_TOKEN` and `FLOWRA_DEVICE_ID=esp32-flowra-01`. A random 32-byte device token was generated locally during implementation if none existed. Its value was not printed, and the file remains gitignored. For a clean checkout, generate and save a random token of at least 32 characters locally. Do not use the public demo password or a Gemini API key as the ingestion token. Restart Next.js after changing server configuration.

The endpoint is disabled with HTTP 503 if its token is missing or too short. It accepts `Authorization: Bearer <device-token>`. Demo sign-in has no authority over this endpoint. No token is sent to dashboard JavaScript. HTTPS is required for any public bridge; plain HTTP is appropriate only for a trusted local/private-gateway connection. Do not enable permissive CORS or put the token in a URL.

## HTTP API

- `POST /api/telemetry`: authenticated ingestion. Returns 202 with server receipt timestamp and sequence, or 400 invalid readings, 401 authentication failure, 409 duplicate/out-of-order, 413 oversized, 415 wrong content type, 429 sender rate limit, 503 not configured.
- `GET /api/telemetry`: public read-only **synthetic demo** data, current connection state, server clock and latest recorded frame. No secrets are returned. Do not use this public demo read API for private utility data.
- No valve-command endpoint exists. All applied internal actions remain virtual. Connected-mode sliders can preview allocation, but applying device changes is disabled.

A frame must include all fields below. The `source` is `connected-simulated-esp32` for the firmware or `http-test-sender` for the bundled Node sender. No missing readings are filled from the internal simulation. Units must match exactly, sensor IDs are fixed, and A/B/C must occur exactly once. Flow and declared demand are bounded to 0–500 L/min; tank/valves to 0–100%. For this synthetic example, outlet cannot exceed inlet. Requested `demand` is an externally supplied synthetic planning input, not a claim of measured household demand.

```json
{
  "schemaVersion": 1,
  "deviceId": "esp32-flowra-01",
  "source": "connected-simulated-esp32",
  "bootId": "esp32-demo-0001",
  "sequence": 0,
  "measuredAt": "2026-11-21T12:00:00Z",
  "tank": { "sensorId": "tank-01", "levelPercent": 78, "unit": "%" },
  "sourceFlow": { "sensorId": "source-01", "flow": 68, "unit": "L/min" },
  "zones": [
    { "zoneId": "A", "inletSensorId": "flow-A-in", "outletSensorId": "flow-A-out", "inlet": 24, "outlet": 24, "demand": 24, "valvePercent": 100, "unit": "L/min" },
    { "zoneId": "B", "inletSensorId": "flow-B-in", "outletSensorId": "flow-B-out", "inlet": 33.6, "outlet": 21.6, "demand": 21.6, "valvePercent": 100, "unit": "L/min" },
    { "zoneId": "C", "inletSensorId": "flow-C-in", "outletSensorId": "flow-C-out", "inlet": 14.4, "outlet": 14.4, "demand": 14.4, "valvePercent": 100, "unit": "L/min" }
  ]
}
```

Use the current UTC timestamp, not the literal example date. It must be within 30 seconds past / 10 seconds future of the server. Boot IDs are 8–40 alphanumeric/hyphen characters; sequence is a nonnegative safe integer and increases within each boot. Timestamps always increase, including across boots. Duplicate/old frames are rejected. Send every five seconds; the server accepts at most one per two seconds and 30 per minute. Bodies are limited to 8 KB, including streamed requests without a Content-Length header. Rejected frames do not replace the last accepted data.

## Test without Wokwi

Start Next.js, sign in with `operator` / `flowra2026`, select **Connected device**, then run in another PowerShell terminal:

```powershell
node scripts/send-telemetry.mjs --scenario=leak --count=6
# Different local port:
node scripts/send-telemetry.mjs --url=http://localhost:3001/api/telemetry --scenario=normal --count=3
```

The script loads its device token privately from `.env.local`. It uses real HTTP and logs only status/sequence, not credentials. It is a **Node HTTP test sender**, not Wokwi or a physical ESP32. Choose `normal`, `leak`, `spike` or `low`. The generated readings are deliberately simple synthetic frames; the received chart records only accepted frames. Switching sources retains the internal simulation independently.

After the sender stops, wait 15 seconds for **Stale readings**, then 45 seconds for **Device disconnected**. Freshness uses the older of the device measurement and server receipt times, so delayed frames do not appear newer than their measurements. Last values and their timestamp remain visibly historical; no fake new samples are appended. Polling failures also mark the feed unavailable. No received frame shows a **No device readings received** state. If a receipt or measurement gap exceeds 15 seconds or a device reboots, the chart's sample window and persistent-leak counter restart; three new consecutive samples are required.

The shared detector applies the same imbalance, consumption and tank thresholds to received data. Forecasts average received demand samples, hold source flow constant and preserve a 2,000 L reserve. The chart's minute axis is elapsed device time, not the accelerated internal simulation clock. Freeze an Ask Flowra snapshot to discuss that exact received frame; the server retrieves its own stored evidence instead of trusting modified browser readings.

## Prototype limits

Storage is process-local memory for one configured device (90 samples/snapshots, 100 alert events). Next.js restarts clear it; multiple server instances do not share it. This is appropriate for a single-process local demo, not durable multi-instance/serverless deployment. Old frozen device snapshots expire after 90 accepted frames; use latest snapshot when prompted.

Bearer authentication does not prove sensor accuracy or device attestation. Replay protection is bounded by this process's retained state and a short timestamp window; persist sequence state, rotate/revoke per-device credentials, add edge abuse controls, audit logs, durable storage and proper user authorization before production. Never use the public demo login to protect sensitive data, Gemini spending or physical hardware controls. The existing Gemini endpoint retains its separate best-effort request limit; public hosting would need stronger abuse protection.


## Isolated Wokwi local test workflow

For a disposable device credential that does not replace the normal token or Gemini key, use `node scripts/wokwi-demo.mjs prepare`, compile the firmware, then `node scripts/wokwi-demo.mjs serve` after a production app build. The helper binds only to 127.0.0.1:3002 and gives the firmware host.wokwi.internal:3002 through the VS Code local gateway. A valid Wokwi extension license and working gateway must still be supplied by the operator. No net.forward rule or public tunnel is needed for this outbound connection.

Private files are .tools/wokwi-demo.json and hardware/wokwi-esp32/secrets.h, both gitignored. Prepare refuses to overwrite them. A configured .bin/.elf also contains the device token and must remain private. Stop Wokwi and the helper server before `node scripts/wokwi-demo.mjs cleanup`; then prepare a new token and rebuild for another test. Cleanup alone does not revoke a credential in a still-running server. Root .env.local is never modified. No device token belongs in a URL, public sketch, browser bundle, log or screenshot.

On 21 November 2026 the locally simulated ESP32 delivered authenticated normal readings to this receiver. Connected device displayed advancing receipt times for sequences 6 through 8. Before each new synthetic sample, the firmware synchronizes its clock from the local endpoint's HTTP Date using a credential-free HEAD request over the private gateway.
